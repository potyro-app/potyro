# @potyro/design

Potyro's design system, as the designer delivered it and as the product consumes it.

> **Tudo em grafite. A cor entra num traço só.** — everything graphite, colour in one stroke.

## The designer's files (`source/`, verbatim)

| File | What it is |
|---|---|
| `DESIGN.md` | The rules: principles, colour, type, shape, space, icons, motion, brand, components, generated apps (§8), the landing (§9), the Potyro app (§10), accessibility (§11), the checklist (§13). Read §1–3 and §11 before any visual work, then the section for the surface you are on. |
| `REDACAO.md` | The voice: how every word Potyro shows is written (pt-BR first). |
| `potyro-tokens.css` | The values. Generated by `potyro-color.js` plus fixed type, space, shape and motion. |
| `potyro-color.js` | The colour clock: every colour is an angle; the system computes the rest. |
| `potyro-logo.svg` | The logo sheet: every variation on one canvas. |

These are the source of truth. A new drop from the designer replaces them; the generated files
below follow (`pnpm gen:tokens`, `pnpm gen:logo`), and the tests say when they are stale.

## What the product uses

- **`tokens.css`** — the designer's tokens, with the Google Fonts `@import` replaced by `@font-face`
  rules for the copies in `fonts/`. The shell is offline-first and ships its fonts. Generated by
  `scripts/tokens.mjs`; `test/tokens.test.ts` fails while it is stale.
- **`fonts/`** — Quicksand (display, 600/700 only, 20px and up), Figtree (body), DM Mono (code);
  latin and latin-ext, variable weight where the family has one. ~145 KB together.
- **`logo/`** — the sheet cut into standalone SVGs by `scripts/split-logo.mjs` (Playwright measures
  each shape): `wordmark-<colour>.svg` and `…-on-dark.svg` for each of the six colours the sheet
  carries (rosa, vermelho, laranja, amarelo, salvia, azul), `wordmark-mono`, `wordmark-large`,
  `tagline` (outlined, never re-typed), `symbol-rosa` / `symbol-rosa-on-dark` (the "y" alone) and
  the four symbol tiles (`symbol-circle-dark` …). Never redrawn, never recoloured by hand (§4.1):
  the sheet's colours predate the clock, so an app's seal takes the nearest colour the sheet has.
- **`src/lucide.ts`** + **`src/lucide-paths.generated.ts`** — the apps' icons (§3.5, #425). An app
  names a Lucide icon (`icon: "shopping-cart"`, kebab-case as on lucide.dev) and the shell draws it
  in the stroke of the logo wherever it shows it: `@potyro/views`'s `Glyph` for the page, `Path2D`
  for a canvas. Every icon is one path in a 24-box, generated from the `lucide` data package by
  `scripts/lucide.mjs` (`pnpm gen:lucide` after bumping `lucide` / `lucide-react` together) with
  Lucide's older names as aliases; it is one lazy chunk (~80 KB gzipped), fetched the first time a
  name is drawn and precached by the shell's service worker. `lucideReady()`, `lucidePath(name)`,
  `lucideKnown(name)`; `test/lucide.test.ts` checks the set.
- **`src/color.ts`** — the colour clock in TypeScript: `cor(x)` for every level of a hue in both
  themes, `categorias(x, n)` for data categories, `vars` / `varsBoth` for the custom properties,
  `apply(el, x)` as DESIGN.md names it. `test/color.test.ts` proves it equals the designer's
  twelve-hour table exactly, and that any angle keeps the contrast guarantees.

## How the shell wears it

`packages/shell/src/styles.css` imports `tokens.css` first and declares only what the shell knows
(insets, chrome room, a person's colour) plus aliases for older names. An app's colour and a chosen
look go through the clock (`app-colour.ts`, `look.ts`): only the angle is kept, both themes' levels
are set as `-l` / `-d` pairs and `.k-traco` picks the theme's. The launchers show `wordmark.tsx`;
the favicon and PWA icons are the symbol tiles.
